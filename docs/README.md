# Documentation

| I want to | Read |
|---|---|
| Know what the phone is like to use | [experience.md](experience.md) |
| See what works, what does not, and how each was checked | [status.md](status.md) |
| Install it | [guides/install.md](guides/install.md) |
| Back up, unbrick or go back to Android | [guides/recovery.md](guides/recovery.md) |
| Change, build and test the packages | [guides/development.md](guides/development.md) |
| Learn how a part works and why | [hardware/](hardware/README.md) |

## Layout

```
docs/
  README.md          this index
  experience.md      day-to-day use
  status.md          feature status, evidence, known problems
  guides/            install, recovery, development
  hardware/          one page per part of the phone, and experiments
```

Keep each page on one topic. Put a new finding in the page for its part,
and put its test result in [status.md](status.md).
